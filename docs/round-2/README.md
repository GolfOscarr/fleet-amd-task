# Round 2

The second round on the MI300X, planned from the artifacts of the first
(`docs/gpu-bringup/`): what is prepared on the laptop first, how the two
sessions on the 1x MI300X VM are spent, the log of what actually ran, and
the results. Written from 2026-09-16 on; branch `local/round-2`.

| File | What |
|---|---|
| [`01-preparation.md`](01-preparation.md) | what the artifacts say; the fault analysed from the plans (every plan quantity is linear in the layer count, so the addresses are the variable); items P1 to P9, each with its deliverable, its laptop check, its time box and what it saves on the VM; the gate before booking |
| [`02-session-plan.md`](02-session-plan.md) | the $27 budget; the reporting protocol; session A and B as rows of literal `laptop.sh` commands with the PASS text, AUTO or DECIDE and the action on FAIL; the fault decision tree; the timing thresholds against the baseline; the queue files; the failure playbook; the expected outputs of 2026-09-15 |
| [`03-session-log.md`](03-session-log.md) | the skeleton to fill during the sessions: the timeline per plan row, the DECIDE rows with rule, measured value and choice, the failures and fixes, the artifacts |
| [`04-results.md`](04-results.md) | the skeleton to fill after: the correctness evidence, the fault's answers, the variants against the 15.6 ms baseline, the per-operator table with the 2026-09-15 numbers prefilled, the counters, what remains open |
| [`05-rehearsal.md`](05-rehearsal.md) | generated by `env/session/rehearse.sh`: every command of both sessions in DRY mode, the exact spelling the scripts use; regenerate after any change to the scripts or the queue files |

The scripts of this round are `env/session/` (the VM stages, the run
queue, the laptop driver; P4 of `01-preparation.md`) and the flags added to
`harness/run_fleet.py` (`--pad-alloc`, `--tile-linears`). The rules for
reaching the VM are unchanged from `docs/gpu-bringup/06-agent-guide.md`.
