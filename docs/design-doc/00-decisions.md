# 00 - Decisions

Every decision the design rests on, with the alternative it beat, the
evidence, and the observation that would reverse it. Decisions carry the
verification level of their evidence: `primary` (ISA, LLVM, config.json),
`checkpoint` (read from the model files), `code` (read in the Fleet source at
`51dce4f`), `derived` (arithmetic from primary facts), `secondary`
(published measurements by others).

Sources are in the discovery sets under `docs/` and in the code-read notes
`docs/fleet/03-runtime.md` and `docs/fleet/04-repo-map.md`.

|---|---|---|---|---|---|
| D1 | Compile for **gfx942**, run in **SPX + NPS1** | gfx950 code objects; CPX partitioning | Our hardware is MI300X; gfx950 objects do not load on it; SPX is the default mode and the one Fleet's runtime assumes (8 XCDs, one agent) | `docs/mi300x/01-architecture.md`, `docs/mi300x/02-chiplet-dispatch.md` (`primary`) | the provided machine is partitioned and cannot be reset |

| D3 | Batch 1, BF16 weights and activations, FP32 accumulation and softmax, greedy decode, 1,024-token prompt, 32 output tokens, no EOS stop | - | Task constraints; EOS disabled so the reference and the Fleet path emit exactly 32 tokens | `docs/task-description.pdf` | - |

## Model execution

| ID | Decision | Rejected alternative | Why | Evidence | Reversed if |
|---|---|---|---|---|---|

| D8 | **Layer 0 dense MLP padded** from intermediate 10944 to **11264** with zero rows in `gate`/`up` and zero columns in `down` | Unpadded 10944; splitting into `gang_linear` + `silu_mul` with an odd tile size | 10944 / 8 = 1368 is not a multiple of 64, so the fused SiLU gang linear cannot tile it, and 10944 is not a multiple of the CK pipeline's `KPerBlock = 256`, so the down projection would silently drop 192 of 10944 columns (`NumLoopK = K / 256` is integer division); 11264 = 8 x 1408 = 44 x 256 satisfies both; cost +3.75 MiB per token (0.08%: 2.5 in gate/up, 1.25 in down), result exact (zeros contribute nothing) | `docs/fleet/04-repo-map.md` (`linear_kernel_ck`) (`code`); arithmetic (`derived`) | never |
| D9 | `q_proj` and `kv_a_proj_with_mqa` **fused into one gang linear** over concatenated rows `[3648, 2048]`, `tile_n = 24` (19 tiles per XCD) | Two ops | The chain model requires consecutive ops to share a tensor; `q_proj` and `kv_a` both read the norm output and neither reads the other's output, so as two ops the second could not be linked; 3648 / 8 = 456 = 19 x 24, no padding needed | `docs/fleet/03-runtime.md` (`code`) | never |
| D10 | Attention as four ops after the fused projection: `mla_prep` (1 task), `mla_attend` (gang, 8 tasks, 5 tiles each), `mla_merge_uv` (gang, 8 tasks, 2 tiles each: one head per tile, merge fused with the `W_UV` product), `o_proj` gang linear with residual | Merge as a single CU task; `W_UV` folded into `o_proj` | A single-workgroup merge would also have to read the 2 MiB `W_UV`, which one workgroup cannot stream quickly; per-head tiles put 16 workers on it; folding `W_UV` into `o_proj` is materialized absorption (D4) | `docs/mla-decode/04-our-kernel-spec.md` (`derived`) | measurement shows the merge off the critical path either way |
| D11 | Split-KV with `BLOCK_H = 16` (all heads share one KV read) and **splits of 32 positions**: 33 splits over `S_max = 1056`, 5 tiles per XCD, tiles past the current length return early | Fewer splits (vLLM's 2); more splits; head splitting | 16 heads sharing one read is the MQA property; 32 splits balance partial-buffer traffic against parallelism at 2% of layer traffic; a static tile count keeps the graph identical every iteration, which the runtime requires | `docs/mla-decode/04-our-kernel-spec.md` (`derived`, `secondary`) | the `P_split` sweep (MIN-23) moves the knee |
| D12 | **Prefer CK's split-KV FMHA pipeline at (QK 576, V 512)** for `mla_attend` if the machine's `ck_tile` instantiates it; the from-scratch kernel spec is the fallback | From-scratch first | The repo already wraps this pipeline for GQA with `kM0 = 16`; if the head-dim pair is supported, phase B is a wrapper and the merge is CK's; days saved | `docs/fleet/04-repo-map.md`, `docs/fleet/99-open-questions.md` Q11 (`code`) | it does not compile, does not fit 57 KiB LDS, or is slower than the spec kernel |

## Runtime and interfaces

| ID | Decision | Rejected alternative | Why | Evidence | Reversed if |
|---|---|---|---|---|---|
| D14 | **`mode = "online"`**. After `compile()` (which runs `init_kernel`) and before `mpk()`, the host sets `step = 1022`, `new_token_nums = 1`, `qo_indptr_buffer = [0, 1]`, `max_seq_length = 1056`, `eos = -1`. The seeded end-of-graph event calls `prepare_next_batch` once before iteration 0 and advances `step` to 1023; the kernel then advances it per iteration and stops after the 32nd. The argmax reduce writes `tokens[step + 1]` directly (a one-line variant), because online mode does not copy `output_tokens` into `tokens` | `mode = "offline"` | Offline mode admits a request by prefilling it from token 0 through the same graph, 8 tokens per iteration, and ignores a preset `step`; online mode takes `step` from the host, which is exactly a hand-over from an external prefill. `qo_indptr_buffer[1]` is what the gang linears read as `num_active_tokens`, and `init_kernel` zeroes it | `docs/fleet/04-repo-map.md`, `docs/fleet/03-runtime.md` (`code`) | online mode needs some other meta tensor we have not traced; then set it the same way |
| D15 | **Hand-over boundary at position 1023**: the reference prefills the full 1,024-token prompt, the latent cache for positions 0..1022 is captured from it, and the Fleet path's first iteration consumes prompt token 1023 at position 1023 and emits the first output token | Fleet starts after the reference's first output token (31 Fleet iterations) | All 32 output tokens then come from the Fleet path, every iteration attends over at least 1,024 positions, and the reference's cache entry for position 1023 becomes a free check on the append task | `docs/task-description.pdf`; `docs/fleet/04-repo-map.md` (`code`) | never |
| D16 | Cache captured from the reference's **module outputs**: hook `kv_a_proj_with_mqa`, split 512/64, apply the model's own `kv_a_layernorm` module and `apply_rotary_pos_emb` with its own cos/sin | Recompute from `output_hidden_states`; invert the decompressed cache | Module outputs are the exact intermediate values; recomputation is equivalent but redundant; inversion is a least-squares solve and not exact | `docs/deepseek-v2-lite/sources/modeling_deepseek.py:831-856`, `docs/deepseek-v2-lite/02-mla.md` (`checkpoint`) | never |
| D17 | The graph is built by a **stand-alone script** in the style of `demo/qwen3/demo_30B_A3B.py`, not a `models/` builder class | Subclass `models/qwen3/builder.py` | The MoE wiring lives in the demo; the builder class has no MoE and is 824 lines of structure we do not need | `docs/fleet/04-repo-map.md` (`code`) | never for this task |
| D18 | Reuse Fleet's **MFMA-based CK linears at M = 1** (15 of 16 rows padded); attention on MFMA 16x16 with M = 16 heads; a VALU GEMV is a later optimization only if a linear measures below the bandwidth band | Write VALU GEMVs first | The padding wastes ALU, not bandwidth, in a memory-bound op; the existing kernels are validated on MI300 | `docs/fleet/04-repo-map.md` (`code`); `docs/acceleration/03-kernel-craft.md` (`derived`) | a linear task measures under 60% of the per-op bandwidth band with the fences and dispatch excluded |
| D19 | **Prefetch depth 4-8 loads in flight per wave** is a requirement on every kernel we write, and a disassembly check on every CK instantiation we reuse | Assume CK pipelines are deep enough | One wave per SIMD is the occupancy of a megakernel; only in-flight loads hide latency | `docs/mi300x/07-achievable-bandwidth.md` (`derived`) | - |
| D20 | Every cross-XCD edge relies on `__builtin_amdgcn_fence(..., "agent")` as the runtime does; we add no hand-written cache-control instructions, and we verify the builtin's lowering by disassembly on day 1 | Inline `buffer_wbl2` / `buffer_inv` asm | The runtime's correctness already rests on that builtin; two mechanisms would be worse than one verified one | `docs/fleet/03-runtime.md`, `docs/mi300x/03-memory-model.md` (`code`, `primary`) | the disassembly lacks `buffer_wbl2 sc1` / `buffer_inv sc1`; then the builtin is replaced in `mpk_atoms.cuh` |

## Decisions withdrawn during the code read

- "VALU for weight GEMVs" (previously locked in `PROGRESS.md`): withdrawn in
  favour of D18. Fleet's linears are MFMA-based and validated; rewriting them
  is not where the time goes.
- "The shared-expert branch overlaps the router" (`docs/fleet/06-our-task-graph.md`):
  withdrawn. The dependency model is a chain (`docs/fleet/03-runtime.md`).
  Replaced by D6, which achieves the same goal (no idle chiplets, no extra
  ops) by construction rather than by scheduling.
- "80 tasks per MoE layer" and "~2,135 tasks per token": superseded by the
  counts in `01-execution-flow.md`, derived by `sources/graph_counts.py`.
